# Medication Reminder

Telegram-приложение для планирования и подтверждения приёма лекарств и выполнения уколов.

Основной интерфейс — Telegram-бот. Telegram Mini App использует ту же базу данных и
подписанную Telegram-идентификацию: в нём доступны приёмы на сегодня, подтверждение
или пропуск приёма, история за 7/30 дней и автоматическое определение часового пояса.

## Локальный запуск

```bash
uv sync --extra dev
uv run uvicorn medication_reminder.main:app --reload
```

Проверка состояния приложения доступна по адресу `http://localhost:8000/health`.

Для запуска PostgreSQL, Redis, применения миграций и запуска Telegram polling:

```bash
docker compose up --build
```

Фоновый запуск и просмотр состояния:

```bash
docker compose up -d --build bot
docker compose ps
docker compose logs -f bot reminder-worker
```

Применение миграций к настроенной базе данных:

```bash
uv run alembic upgrade head
```

### Telegram-бот

Задайте токен, полученный у BotFather, в `.env`:

```dotenv
MEDICATION_TELEGRAM_BOT_TOKEN=123456:telegram-token
```

Опциональный `MEDICATION_TELEGRAM_MINI_APP_URL` должен быть валидным HTTPS URL.
Если он задан, бот показывает кнопку Mini App при выборе часового пояса.
URL должен вести на публичный HTTPS-адрес страницы `/mini-app` этого приложения;
backend проверяет подпись и срок действия Telegram `initData` перед чтением данных
или изменением статуса. Mini App показывает приёмы на сегодня, историю за 7/30 дней,
назначения и позволяет отметить приём, приостановить, возобновить или завершить курс.

Для локальной разработки без сервера можно открыть наружу только изолированный Mini App
процесс, не публикуя остальные API-маршруты:

```bash
uv run uvicorn medication_reminder.mini_app_local:app --host 127.0.0.1 --port 8001
cloudflared tunnel --url http://127.0.0.1:8001 --no-autoupdate
```

Полученный HTTPS URL с суффиксом `/mini-app` задаётся в
`MEDICATION_TELEGRAM_MINI_APP_URL`. Временный tunnel работает, пока запущены обе
локальные команды.

Для запуска polling вне Docker после отдельного запуска PostgreSQL и применения
миграций:

```bash
uv run python -m medication_reminder.telegram
```

При первом `/start` пользователь выбирает часовой пояс из предложенного списка или
вводит IANA ID вручную. Telegram Bot API не передаёт часовой пояс пользователя.

Команда `/add` и кнопка `➕ Добавить` запускают пошаговый мастер назначения. Состояние
мастера и блокировка параллельных действий хранятся в Redis, поэтому заполнение можно
продолжить после перезапуска бота. Назначения и события хранятся в PostgreSQL.

Для бессрочного назначения при создании материализуются первые 90 календарных дней.
Фоновый worker идемпотентно поддерживает это скользящее окно заполненным.

### Доставка напоминаний

Сервис `reminder-worker` выбирает наступившие события небольшими конкурентно-безопасными
пакетами и отправляет Telegram-уведомления. Пользователь выбирает повтор через 15,
30 или 60 минут и может временно выключить уведомления. Ошибка доставки повторяется через 60 секунд,
а зависшая попытка может быть перехвачена через 5 минут. Значения настраиваются через
`MEDICATION_REMINDER_*` из `.env.example`.

Кнопка «Отложить» предлагает 15, 30 или 60 минут. Отложенное напоминание не изменяет
расписание и следующие приёмы курса и не может выйти за дедлайн. Для набора дедлайном
служит конец его окна; отдельный приём остаётся доступен до конца локального дня.
После дедлайна worker автоматически переводит событие в `missed`.

### Управление назначениями

Кнопка `💊 Мои назначения` открывает список курсов с дозировкой, графиком, сроком,
ближайшим приёмом и текущим статусом. Активный курс можно приостановить или завершить, а приостановленный —
возобновить. Завершение требует отдельного подтверждения и отменяет все необработанные
события. При возобновлении просроченные за время паузы события отменяются, поэтому бот
не присылает накопившиеся напоминания задним числом; будущие даты сохраняются.

Активный курс можно изменить кнопкой `✏️ Изменить`: отдельно дозировку, график либо
оба параметра, оставшееся количество приёмов или дату окончания. Изменение применяется
только к будущим запланированным событиям. Назначение можно удалить с отдельным
подтверждением; вместе с ним удаляется его история.
Уже наступившие и завершённые события сохраняют прежние название, форму, дозировку
и условие приёма относительно еды,
а для нового графика создаётся следующая версия расписания. Поддерживаются ежедневный
приём, интервал в днях, дни недели, несколько времён в сутки и ручной ввод времени.
Для режима `Будни / выходные — разное время` бот отдельно спрашивает время Пн–Пт и
Сб–Вс, например 06:30 в будни и 09:00 в выходные.

При добавлении нового препарата мастер сразу предлагает выбрать способ напоминания:
набор `Утро`, `День`, `Вечер` либо отдельное точное время. Отсутствующий стандартный
набор создаётся автоматически. Если выбран набор, отдельный шаг ввода времени
препарата пропускается: пользователь задаёт только периодичность и длительность курса,
а уведомления следуют окну набора. Режим разных времён в будни и выходные доступен
только для отдельного точного времени. Назначение, расписание и включение в набор
сохраняются одной транзакцией.

Кнопка `📊 История` показывает события за последние 7 или 30 локальных календарных
дней. Вверху отображаются количество выполненных, пропущенных и ожидающих приёмов,
а также процент соблюдения графика среди завершённых событий. Отменённые при
редактировании курса события в статистику не входят.

Кнопка `🗂 Наборы` позволяет объединить несколько свободных активных назначений в
режим `Утро` (06:00–12:00), `День` (11:00–17:00) или `Вечер` (18:00–23:00). Набор хранится отдельно от
назначений и фиксирует часовой пояс и окно напоминаний. Одно назначение может входить
только в один набор. В течение окна бот отправляет одно общее напоминание со всеми
ожидающими препаратами. Каждый приём можно подтвердить отдельно либо отметить весь
набор кнопкой `✅ Принять всё`; до подтверждения уведомление повторяется. Для
назначений внутри активного набора отдельные параллельные напоминания не отправляются.
Пользовательский интерфейс использует три понятных набора: `Утро`, `День` и `Вечер`.
У набора редактируется состав. При удалении набора сами
назначения и их графики сохраняются.

### Семья

Раздел `👨‍👩‍👧 Семья` позволяет владельцу создать группу и одноразовой ссылкой
пригласить участника. Для участника можно выбрать самостоятельное управление либо
режим, в котором он только отмечает назначенные владельцем приёмы. Владелец видит
сегодняшний статус семейных назначений, может переименовать или удалить участника и
группу; удаление семейного доступа удаляет только созданные через него назначения.

### Данные пользователя

- `/mydata` выгружает настройки, назначения и историю в JSON;
- `/delete_me` после отдельного подтверждения удаляет все данные пользователя;
- бот предназначен для напоминаний и не назначает лечение и не проверяет совместимость
  препаратов.

API предоставляет `/health` для проверки процесса и `/ready` для проверки PostgreSQL
и Redis. Рекомендации по эксплуатации находятся в [docs/operations.md](docs/operations.md).


Интеграционные проверки используют отдельный PostgreSQL и для каждого запуска создают
изолированную временную схему:

```bash
docker compose --profile test up -d test-postgres
MEDICATION_TEST_DATABASE_URL=postgresql+asyncpg://medication:medication@localhost:55432/medication_test uv run pytest -m integration
docker compose --profile test down
```

Без `MEDICATION_TEST_DATABASE_URL` эти тесты безопасно пропускаются. Обычные unit-тесты
не требуют Docker или работающей базы данных.

### Статистика владельца

Команда `/stats` доступна только в личном чате пользователям из
`MEDICATION_TELEGRAM_ADMIN_IDS` (JSON-массив числовых Telegram ID, например `[123456789]`).
По умолчанию доступ закрыт. Кнопки выбирают сегодняшний день, последние 7 или 30
календарных дней, включая сегодня; границы периода — по Москве.

Сводка показывает пользователей и новые регистрации, уникальную активность в боте
и Mini App, текущее число активных курсов, наборов и семейных групп, действия с
приёмами и состояние отправки напоминаний. Повторные отметки считаются отдельными
действиями; человек, использующий оба интерфейса, считается одним активным пользователем.
Отправленные групповые напоминания считаются по сообщениям, а не по числу препаратов.
Ошибки отражают текущее состояние заданий, поэтому после успешной повторной отправки
задание перестаёт считаться ошибочным. Данные отправок ограничены сроком хранения
попыток (по умолчанию 90 дней); отправка не подтверждает прочтение пользователем.

Новый учёт активности начинается после миграции `20261103_13_user_activity`:
сообщения/нажатия в личном чате и загрузка главного экрана Mini App, включая его
обновления, пока приложение открыто. Автоматические напоминания активностью не считаются.
В БД сохраняется одна запись на пользователя, московскую дату и канал с последним
временем взаимодействия. Тексты сообщений и медицинские данные в эту таблицу не попадают;
удаление аккаунта удаляет и его активность.

В сводке также разделены аккаунты без назначений и наборов, аккаунты только
с наборами и аккаунты с назначениями. Первые три категории не пересекаются;
завершённый курс тоже считается сохранённым назначением. Отдельно показаны владельцы
активных курсов, новых назначений и наборов за период и число пользователей, по
назначениям которых были отметки «принято». Число пользователей не умножается
на число их курсов. Семейные назначения относятся к получателю. Настройка аккаунта
отражает текущее состояние сохранённых объектов, а не полную историю до их удаления.
