# Эксплуатация

## Перед запуском

1. Хранить `MEDICATION_TELEGRAM_BOT_TOKEN` только в секретах окружения.
2. Использовать отдельные пароли PostgreSQL и Redis; не публиковать их порты наружу.
3. Применить `alembic upgrade head` до запуска бота и worker.
4. Для Mini App указать публичный HTTPS URL вида `https://example.org/mini-app`.
5. Проверить публичный `/health` и внутренний `/ready` после развёртывания.

## Наблюдение

- перезапускать `bot`, `reminder-worker` и `api` при сбое;
- собирать stderr/stdout и оповещать по ошибкам worker;
- опрашивать `/ready` только из внутренней Docker-сети; публичный путь закрыт Caddy;
- HTTP 503 от внутреннего `/ready` означает недоступность PostgreSQL или Redis;
- следить за числом событий в `due`, неуспешных попыток доставки и задержкой worker.

## Резервные копии

Ежедневно создавать зашифрованную резервную копию PostgreSQL, хранить несколько
версий отдельно от сервера приложения и регулярно проверять восстановление на
временной базе. Redis содержит только временное состояние мастеров и не заменяет
резервную копию PostgreSQL.

Каталог `BACKUP_DIR` должен быть внешним зашифрованным диском или подключённым
off-site хранилищем. Пароль хранится в отдельном файле с правами `0600`:

```bash
BACKUP_DIR=/mnt/offsite/vovremya \
BACKUP_PASSPHRASE_FILE=/run/secrets/vovremya-backup-passphrase \
./scripts/backup-postgres.sh
```

Эту команду следует запускать ежедневно системным таймером или cron. Скрипт хранит
30 дней по умолчанию; срок меняется через `BACKUP_RETENTION_DAYS`.

Не реже раза в месяц проверить полный restore в автоматически созданную временную БД:

```bash
BACKUP_PASSPHRASE_FILE=/run/secrets/vovremya-backup-passphrase \
./scripts/test-postgres-restore.sh /mnt/offsite/vovremya/medication-YYYYMMDDTHHMMSSZ.dump.enc
```

## Обновление

1. Сделать резервную копию PostgreSQL.
2. Собрать новый образ.
3. Применить миграции.
4. Перезапустить API, worker и бот.
5. Проверить внутренний `/ready`, публичный `/health`, логи и тестовое напоминание.

## Инциденты и приватность

Пользователь может получить данные командой `/mydata` и удалить их командой
`/delete_me`. Не включать названия препаратов, дозировки, Telegram initData или токен
бота в прикладные логи. При компрометации токена немедленно перевыпустить его через
BotFather и обновить секрет окружения.
